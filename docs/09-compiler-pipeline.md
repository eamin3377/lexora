# 09 — Compiler Pipeline Explorer

`/tools/pipeline` — the platform's centerpiece synthesis: one program traveling the full journey, every stage animated, every intermediate artifact inspectable.

## 1. Layout

A horizontal conveyor of nine stage cards (vertical on mobile):

```
Source → Lexical → Syntax → Semantic → IR → Optimize → Codegen → Assembly → Executable
 (ink)  (marigold) (cobalt)  (orchid)  (orchid) (leaf)    (cobalt)  (ink)     (leaf)
```

Top: program selector (curated examples: expression, if/else, while-loop GCD, function call) or "use my code" (subset-C). Transport bar (shared component) drives a **global clock**: playing runs the artifact through all stages; clicking a stage card expands it into a full-height inspector while the conveyor shrinks to a breadcrumb strip.

## 2. Stage-by-stage animation spec

1. **Source:** code card; characters shimmer as they're about to be consumed.
2. **Lexical Analysis:** embedded mini Lex Machine — chips pop from the character stream and pile into a token queue that visibly *feeds* the next stage through a hatch.
3. **Syntax Analysis:** chips are eaten by the parser; parse tree grows (shift/reduce plates animate in compact form); tree morphs into AST at stage exit.
4. **Semantic Analysis:** the AST gets *decorated live* — a checker cursor walks the tree; type annotations stamp onto nodes (`int`, `float`); the **symbol table** fills row-by-row on the side with scope-depth indentation; a type error (in error demos) paints the offending subtree coral with the coercion/conflict explained.
5. **Intermediate Code:** AST nodes *unroll* into three-address code — each TAC line flies out of the subtree that produced it (hover any TAC line ↔ its AST subtree highlights). Temporaries `t1, t2…` birth with a counter. Alternate views: quadruples table, control-flow graph (basic blocks as cards, edges ink-drawn).
6. **Optimization:** pass-by-pass, before/after in a split diff: constant folding (operands slide together and fuse into the constant), dead-code elimination (lines gray out, crumble, and fall away), common-subexpression elimination (duplicate expressions connected by a lasso, second one replaced by the temp), loop-invariant motion (a line physically lifts out of the loop body). Pass pipeline is toggleable — learners compose their own pass order and watch outcomes differ.
7. **Code Generation:** TAC lines translate to assembly with a **register allocation strip**: registers as labeled slots; values move in/out; a spill animates as a value being pushed off to a stack card. Target selector: x86-64 / RISC-V (RISC-V default for teaching clarity).
8. **Assembly:** final listing with hover-sync back to TAC → AST → tokens → source characters (the full provenance chain — hovering *one assembly line* lights the entire history of where it came from, across all stages).
9. **Executable:** a play button; runs (via the WASM toolchain for real programs, or the educational interpreter for the subset language); output pill shows the result; a tiny "it's alive" pulse.

## 3. Modes

- **Tour mode** (default for first visit): narrated autoplay, 90 seconds, captions.
- **Inspect mode:** free clicking/scrubbing, all hover-provenance active.
- **Compare mode:** two pipelines side-by-side (e.g., `-O0` vs `-O2`; or the same program with a changed line — diff ripples downstream through every stage).
- **Lesson mode:** stages beyond the current curriculum position are sketched in "blueprint" style (ink outlines, unfilled) — curiosity bait that fills in as the learner progresses. This is the same visual used in the dashboard progress heatmap.

## 4. Honesty principle

For curated subset-C programs, every artifact is generated by the platform's real educational compiler (not hand-authored fakes), so edits genuinely propagate. The provenance hover chain is powered by source-map-like metadata carried through every phase — this is the core data-model requirement for the whole product (see doc 17).
